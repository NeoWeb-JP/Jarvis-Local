# Experimental VoicePipeline speaker identity

Install Jarvis Local 0.16.0 and confirm it works before changing the test VoicePipeline. This modifies the transcription returned by the test STT provider and is only compatible with Jarvis Local 0.16.0 or later. Do not point your normal assistants or other conversation agents at the modified test provider until validated.

The marker includes the speaker result and the original transcript. It is signed with an HMAC key shared only between Home Assistant and VoicePipeline. It is visible as encoded text in Assist speech-to-text traces and should be treated as private data. Its purpose is request correlation, not identity authentication or access control. Unknown speakers remain ordinary transcripts. Invalid, expired or replayed markers are rejected; no action is run. Each profile has its own confidence threshold. Testing against overlapping speech and wrong matches is essential.

On the VM in `/opt/voicepipeline`, download the `wyoming_server.py` file from this repository. Preserve your existing file and mount the patch over `/app/pipeline/wyoming_server.py`. The patch is based on upstream source SHA-256 `973fa024b093aa3623fe97c6ec48eb2b7feba8f65f01f6fc7ffa0e372b94ba2d`; compare against the currently running image before applying. A later upstream update may require a new patch.

Generate one random secret, save it in a private root-only environment file on the VM and in `/config/jarvis_voice_id.json` on Home Assistant. Never put those files into GitHub, logs, or chat. The JSON has `secret` and `profiles` keys. Profiles map the exact case-insensitive VoicePipeline enrolled name to `{ "name": "spoken name", "min_confidence": 0.75 }`. Adjust the threshold only after controlled speaker testing. Restart Home Assistant after editing this file. The HA and VM clocks must be correct (marker maximum age 30 seconds).

The marker is generated only for VoicePipeline matched speakers. Restarting/recreating the container retains `/data` and `/models` if the existing bind mounts remain. Remove the override and restart the container to roll back. Test first with one satellite and non-destructive requests; Jarvis currently personalises only short good-morning routine replies by prefixing the selected name. Longer existing morning replies are also prefixed; other responses remain unchanged. No speaker ID is used for authorization.
